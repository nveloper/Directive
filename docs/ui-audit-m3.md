# Material 3 기준 재평가

앱이 Material You 색 체계를 쓰므로, 기준은 Google Material 3로 잡는다.

## 1. 기준의 출처

- **글자·모양·컴포넌트 크기:** Google이 배포하는 `@material/web` 2.2.0 패키지의 디자인 토큰 파일(`tokens/v0_192/*.scss`)에서 직접 읽었다. 공식 사이트 m3.material.io는 이 작업 환경의 네트워크 설정에서 막혀 있어 열지 못했다.
- **창 크기 구간·여백:** 토큰 파일에 없어 기억에 의존했다. 공식 문서로 다시 확인해야 한다.
- **Apple HIG:** 참고용으로만 적었고, 기억에 의존한 값이다.

### 기억에 의존한 값 (확인 필요)

- 창 크기 구간: 600 미만은 compact(폰), 600~839는 medium(태블릿 세로), 840~1199는 expanded(태블릿 가로), 1200 이상은 large
- 화면 여백: compact 16, medium·expanded 24
- 간격: 4dp 격자
- 최소 터치 영역: 48dp. Apple은 44pt이고, 본문 기본 크기는 17pt

## 3. 측정 방법

- 데모를 폰(412×915), 태블릿 세로(834×1194), 태블릿 가로(1194×834)의 터치 화면으로 띄웠다.
- 화면은 목록, 상세, 보드, 달력, 새 작업, 알림, 설정이다.
- 화면에 보이는 모든 글자의 실제 크기와 줄 높이, 누르는 요소의 크기, 여백 값을 읽었다. `zoom` 확대까지 반영한 값이다.
- 비교를 위해 마우스로 쓰는 PC(1440×900)에서도 같은 방식으로 쟀다.
- 소스 코드에 직접 적힌 크기 값도 세었다.

## 4. 결과

### 4.1 글자: 스케일과 맞는 조합이 거의 없다

- **터치 화면:** 크기와 줄 높이 조합이 화면마다 7~18가지인데, 스케일과 맞는 조합은 하나도 없다. 예를 들어 13px은 1.15배로 확대되어 14.9/21.7이 된다.
- **PC:** 확대가 없는데도 목록 16가지, 상세 21가지 조합 가운데 맞는 것은 페이지 제목 28/36 하나다.
- **원인:**
  - 줄 높이를 1.45 비율로 계산해 17.4·18.9·20.3 같은 소수 값이 나온다.
  - 소스에서 `font-size:13px`이 93번 쓰인다. 13px은 스케일에 없는 크기다.
  - 12px이 124번 쓰이는데, Body S나 Label M으로 쓰려면 줄 높이가 16이어야 한다.
- **역할도 어긋나 있다.** M3 목록에서 항목 제목은 Body L(16)인데 지금은 15/500을 쓴다. 다이얼로그 제목은 Headline S(24)인데 지금은 20/500이다.

### 4.2 간격: 4 격자를 벗어난 값이 약 350곳

- 소스에서 여백·간격 값을 세면 10px이 78곳, 6px 68곳, 2px 45곳, 14px 28곳, 5px 21곳, 9px 19곳, 18px 11곳이다. 그 밖에 1·3·7·11·13·22·26·30·34px도 있다.
- 터치 화면에서는 이 값에 1.08이나 1.15를 곱하므로, 화면에 나오는 여백이 사실상 모두 격자 밖이다.

### 4.3 누르는 영역: 상세·설정·새 작업 화면이 기준 미달

| 요소 | 크기(px) | 기준 |
|---|---|---|
| 체크리스트 체크·캘린더 체크·파일 추가 | 19~22 | 40~48 |
| 체크리스트 위/아래/삭제·댓글 삭제 | 24~25 | 40~48 |
| 상세 패널의 선택 상자·날짜·편집·닫기·올리기 | 35~37 | 40~48 |
| 설정 메뉴 항목·닫기 | 35~37 | 48 |
| 보기 전환(목록·보드·달력) | 35 | 40 |
| 달력 이동·주/월 전환·달력 안의 작업 | 32~37 | 40 |
| 알림 "모두 읽음"·알림 켜기 | 20~23 | 40 |
| 탭 | 43~44 | 48 |
| 폰 상단 검색 | 24 | 48 |

### 4.4 높이

- 소스에 적힌 높이 값이 24가지다(20·22·24·26·28·30·32·36·38·40·44 …).
- M3 컴포넌트가 쓰는 높이는 32·40·48·56·64·72 정도면 충분하다.

### 4.5 근본 원인

- `app.js`에 인라인 `style="..."`이 578곳이고, 그 안에 숫자를 직접 적는다. 그래서 공통 기준이 없다.
- 화면을 고칠 때마다 근처 값으로 맞추다 보니 비슷하지만 다른 값이 쌓였다. 이것이 "정갈하지 못한" 인상의 정체다.
- 지난번 터치 화면 `zoom` 조치는 증상을 키웠다. 크기는 커졌지만 모든 값이 격자를 벗어났다.

## 5. 고치는 방법 제안

1. **토큰부터 만든다.**
   - `styles.css`에 글자 역할 클래스를 둔다(`.t-title-m`, `.t-body-l`, `.t-label-l` …). 각 클래스는 크기·줄 높이·굵기·자간을 한 번에 지정한다.
   - 간격 변수는 4·8·12·16·24·32만 둔다.
   - 컴포넌트 높이 변수를 둔다(칩 32, 버튼 40, 탭 48, 2줄 목록 72 등).
2. **`zoom`을 없앤다.**
   - 터치 화면에서 커 보여야 하는 곳은 역할 자체를 바꾼다. 예를 들어 목록 제목은 Body L(16)이 M3 기준이므로 확대 없이도 지금보다 크다.
   - 누르는 영역은 48로 넓히되 보이는 아이콘은 24로 둔다.
3. **인라인 숫자를 토큰으로 바꾼다.** 화면 단위로 진행한다: 목록 → 상세 → 새 작업 → 설정 → 알림 → 보드·달력.
4. **화면마다 이 문서의 측정 스크립트를 다시 돌린다.** 완료 조건은 세 가지다.
   - 스케일 밖 글자 조합 0
   - 4 격자 밖 간격 0
   - 40 미만 터치 영역 0

손대는 범위가 `app.js` 전반이라 한 번에 바꾸기보다 화면 단위 커밋으로 나눈다.
